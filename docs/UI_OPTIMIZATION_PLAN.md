# 提取/合并流程 UI 优化方案

## 一、当前问题

1. **信息重复**：每次扫描先打「ℹ️ 正在扫描…」，进度条结束后再打「✅ 从 X 目录提取到 N 条」→ 同一件事两行，显得啰嗦。
2. **层级不清**：阶段标题（【输入】【输出】）、扫描结果、合并结果、CSV 混在一起，没有明显分组。
3. **图标不统一**：有的用 ℹ️/✅/🔍，有的用 📁/📋，风格混用。
4. **行数过多**：合并模式约 4 次扫描 × 3 行 + 阶段提示 + 合并 + CSV ≈ 18+ 行，一屏难扫完。

---

## 二、优化原则

- **少而精**：能合并成一句的不拆成两句；进度条结束时在同一行或紧接着给结果。
- **分层明确**：用简短分隔/小标题区分「阶段 → 子步骤 → 结果」。
- **风格统一**：流程内统一用 1～2 种图标（如 ✅ 结果、▶ 步骤），避免到处堆 emoji。
- **结果可扫**：最后给 1～2 行「总结」（共提取/合并多少、CSV 路径）。

---

## 三、具体方案

### 3.1 提取阶段（输入/输出）

**现状：**
```
【输入】从英文源提取翻译…
ℹ️ 正在扫描 English Keyed 目录中的 2 个文件...
扫描Keyed: [████...] 100% (2/2) ℹ️
✅ 从Keyed 目录提取到 29 条 Keyed 翻译
ℹ️ 正在扫描 Defs 目录中的 4 个文件...
...
```

**优化后：**
```
【输入】英文源
  Keyed   [████████████] 100% → 29 条
  Defs    [████████████] 100% → 5 条
【输出】现有翻译
  Keyed   [████████████] 100% → 29 条
  DefInjected [████████] 100% → 5 条
```
- 进度条与结果合一：进度到 100% 后在同一行或下一行紧跟「→ N 条」，不再单独一行「从 X 目录提取到 N 条」。
- 阶段下用固定两行「Keyed / Defs 或 DefInjected」，子项缩进，结构一眼能看清。

**实现要点：**
- 在 `extract_all_translations` 或各 extractor 中：进度条结束时输出「→ N 条」而不是再调一次 `print_success`。
- 或：保留现有进度条，去掉各 extractor 返回后 manager 里的「从 X 目录提取到 N 条」重复文案，改为在阶段结束时打一行汇总，如「输入：Keyed 29 条，Defs 5 条」。

### 3.2 合并阶段

**现状：**
```
正在合并 Keyed ...
✅ Keyed 智能合并完成！共处理 29 条翻译（更新: 29 条，新增: 0 条，不变: 0 条，过时: 0 条，未识别: 0 条，重复: 0 条）
正在合并 DefInjected ...
DefInjected 智能合并完成！共处理 5 条输入、5 条现有，需写入 0 条（全部一致）
```

**优化后：**
```
合并 Keyed       → 29 条（更新 29，新增 0，不变 0）
合并 DefInjected → 5 条（更新 0，新增 0，不变 5）
```
- 合并结果单行化：Keyed 与 DefInjected 统一为「合并 X → N 条（更新，新增，不变）」。
- DefInjected 即使需写入 0 条（全部一致）也显示同一格式，便于扫读。

### 3.3 结尾与 CSV

**现状：**
```
ℹ️ 正在导出 29 条翻译到CSV...
导出CSV: [████...] 100%
✅ CSV文件已生成: C:\...\extracted_translations.csv
```

**优化后：**
```
导出 CSV [████████████] 100% → extracted_translations.csv
```
- 一行包含：动作 + 进度 + 结果文件名；路径过长时可只显示相对路径或文件名，完整路径放日志。

### 3.4 交互流程（步骤 1～4）

- 保持现有「【步骤 N/4】标题」和分隔线，仅做微调：同一步骤内少用多余 ℹ️/📁，用缩进区分「说明 vs 选项」。
- 配置确认：保持「数据来源 / 输出目录 / 冲突处理 / 文件结构」的 key-value 展示，可考虑表格化或固定宽度对齐，便于扫读。

### 3.5 图标与风格

- **流程内**：步骤/阶段用「【输入】【输出】」或「▶」即可；成功/结果用「✅」或直接「→」。
- **避免**：同一流程中 ℹ️/🔍/📁/📋 混用过多；优先用文字+缩进表达层级，图标做点缀。

## 四、实施顺序建议

| 优先级 | 内容 | 涉及文件 |
|--------|------|----------|
| P0 | 提取阶段：进度条结束与「→ N 条」合一，去掉重复「从 X 目录提取到 N 条」 | manager.py, 可选 extractors (keyed/defs/definjected) |
| P0 | 合并结果单行化（Keyed/DefInjected 各一行，括号内简要统计） | manager.py |
| P1 | CSV 导出单行化（进度+文件名一行） | manager.py |
| P1 | 阶段标题下子项缩进（【输入】【输出】下的 Keyed/Defs/DefInjected） | manager.py 或 extractors |
| P2 | 交互步骤内图标收敛、配置确认对齐 | interaction.py, ui_style.py（若需） |

## 五、预期效果（合并模式示例）

**优化前（约 18+ 行）：** 多行重复、层级不明显。  
**优化后（约 10～12 行）：**
```
【输入】英文源
  Keyed   [████████████] 100% → 29 条
  Defs    [████████████] 100% → 5 条
【输出】现有翻译
  Keyed   [████████████] 100% → 29 条
  DefInjected [████████] 100% → 5 条
合并 Keyed       → 29 条（更新 29，新增 0，不变 0）
合并 DefInjected → 5 条（需写入 0，全部一致）
导出 CSV [████████████] 100% → extracted_translations.csv
```
- 行数减少、层级清晰、结果集中，便于扫读和排错。

---

如认可该方案，可从 P0 两项开始改（提取结果合并到进度行 + 合并结果单行化），再按 P1/P2 逐步收口图标与格式。
